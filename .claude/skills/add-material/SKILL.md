# 新建学习素材

完成后素材目录里有 `audio.m4a`、`en.srt`、`zh.srt` 三个文件，并且登记在 `materials/catalog.json` 里。**只有登记过的素材才会出现在小程序里**，登记是最后一步，前面任何一步没完成都不要登记。格式要求见 `docs/03-素材格式.md`，开始前读一遍。

**这个 skill 不生成释义。** 做完后提醒用户：把要解释的词写进 `words.txt`，再用 `word-notes` 生成释义。

**下面所有命令都由你运行，不要让用户手动执行，也不要把命令贴给用户让他去跑。** 用户只看结果。

## 1. 准备素材目录

先看用户给的是哪种输入。

### A. 一个文件夹（常见）

用户把一个音频或视频和英文字幕放在同一个文件夹里，通常就是 `materials/` 下新建的文件夹。

- 文件名随意，例如 `news.mp3` + `eng.srt`。
- 可以带一个自带的中文字幕。

直接运行：

```bash
python3 scripts/material.py ingest "<文件夹>"
```

脚本会做这几件事：

- **识别字幕**：按内容区分英文和中文字幕，英文的保存为 `en.srt`，自动转成 UTF-8。
- **中文字幕**：如果自带了，而且和英文一一对应，就保存为 `zh.srt`，第 3 步就不用翻译了。
- **生成音频**：生成 `audio.m4a`（AAC 单声道 48kbps），并核对时长和源文件一致。
- **清理源文件**：都成功后，把源文件移到废纸篓。
  - 文件夹在 `materials/` 下：音频、视频、原字幕都移走，目录里只留标准文件。
  - 文件夹在别处：只移走视频，音频和字幕保留。

几种要停下来的情况：

- **文件夹名不能当 slug**（比如有大写、空格或中文）：脚本会报错。根据内容起一个 slug，和用户确认后加 `--slug <slug>` 重新运行，脚本会把文件夹改成这个名字。
- **用户要保留源文件**：加 `--keep`。
- **其他报错**（多个音频、没有英文字幕、时长对不上等）：源文件都不会动。把错误原样告诉用户，不要自己手动删除或移动文件。

### B. 分散的文件

用户分别给出字幕和音频（或视频）的路径时：

1. 根据内容起一个 slug（小写英文加连字符，如 `running-late`），和用户确认后再建目录。slug 是学习进度和生词本的关联键，定了就不改。`materials/<slug>/` 已存在时，说明里面已有哪些文件，问用户是补充还是换一个 slug，不要覆盖。
2. 英文字幕复制为 `materials/<slug>/en.srt`，不是 UTF-8 的转成 UTF-8。源字幕保留。
3. 提取音频：

   ```bash
   python3 scripts/material.py extract <slug> "<视频或音频文件>"
   ```

   源文件是视频时，确认无误后会移到废纸篓（`--keep` 保留）；是音频时保留。

### 两种情况都适用

- 没有英文字幕时停下来告诉用户，不要自己听写。
- 用户下载的原始文件正好叫 `audio.m4a` 时，`ingest` 会检查规格：不是单声道 48kbps 的，就当作原始文件，先改名再转换。
- 已经是标准规格的 `audio.m4a`，脚本不会覆盖；要重新生成的话，先问用户，再把旧文件移到废纸篓后运行。
- 字幕最后一句比音频长 3 秒以内时，校验只提醒，生成数据时会自动截断；超过 3 秒会报错，多半是配错了音频，要告诉用户。
- 只是给已有素材翻译或重译字幕时，直接做第 3 步。

## 2. 看字幕

读一遍 `en.srt`。很多字幕会把一句话拆成好几段（例如新闻字幕按屏幕宽度断句），这很正常，不用改，翻译时按下面的规范处理。

## 3. 翻译中文字幕

`zh.srt` 已存在时（包括第 1 步用了自带的中文字幕），除非用户要求重译，否则跳过这一步。

1. 完整读一遍 `references/translation-guide.md`。
2. 通读整份 `en.srt`，理解话题、人物关系和语气，再逐句翻译。
3. 写入 `zh.srt`：句数、序号、时间轴和 `en.srt` 完全一致，只替换文字。

## 4. 校验

```bash
python3 scripts/material.py check <slug>
```

有「错误」就改，直到通过。这时还没有 `notes.md`、也还没登记，出现这两条提醒是正常的。

## 5. 登记

根据字幕内容定下素材信息，然后登记：

- **title**：简短的英文标题，概括内容，如 `Running Late`。
- **title-zh**：简短的中文标题，如 `差点迟到`。
- **level**：根据词汇和句子难度估计的 CEFR 等级，A1–C2。
- **tags**：1–3 个中文话题标签，逗号分隔，如 `职场,对话`。
- **source**：用户提到素材来源时填写，否则不填。

```bash
python3 scripts/material.py register <slug> --title "Running Late" --title-zh 差点迟到 --level B1 --tags 职场,对话
```

登记时会自动记下处理时间，小程序首页按这个时间排序，新的在前。重译字幕等已登记素材的操作，再运行一次 register 只会更新信息，处理时间不变。

登记后生成小程序数据：

```bash
python3 scripts/material.py build <slug>
```

## 6. 汇报

简短告诉用户：

- slug、标题、难度、标签，音频时长和大小、句数。
- 哪些源文件移到了废纸篓，中文字幕是翻译的还是自带的。
- 下一步：在 `materials/<slug>/words.txt` 里每行写一个要解释的词或短语，然后用 `/word-notes <slug>` 生成释义。

不要自动提交 git，由用户决定。
