# 发布新版本

所有命令都由你运行，不要让用户手动执行。

## 1. 先看计划

```bash
python3 scripts/release.py --dry-run
```

- **报「还有没提交的改动」**：把改动列给用户，问是否提交。用户同意后按改动内容写一条中文提交说明，提交后重新运行这一步。不要擅自提交。
- **报「构建后小程序数据有变化」**：说明最新的素材数据没提交，处理方式同上。
- **报素材校验没通过**：把错误告诉用户，先修素材。

## 2. 确认后执行

把计划（仓库、新 tag、ref 的变化、素材数量）告诉用户。推送会改动 GitHub 仓库，**用户明确同意后**再运行：

```bash
python3 scripts/release.py
```

脚本会：更新 `config.js` 的 ref 并提交、打 tag、推送分支和 tag，然后逐个检查 jsDelivr 上的音频能否访问。推送失败时会自动删掉本地 tag，修好问题后重新运行即可。

## 3. 汇报

- 新 tag，推送结果，每份音频能否访问。
- 提醒用户：在微信开发者工具里重新上传小程序，新的 ref 才会生效。

## 规则

- 每次发布都用新 tag，不要删除、移动或复用已推送的 tag。jsDelivr 会永久缓存 tag 下的文件，复用会让手机拿到旧音频。
