# 生成释义

输入是一个素材目录：`materials/<slug>/`，或者直接给 slug。目录里必须有 `en.srt` 和 `words.txt`。

`words.txt` 的每一行都要有释义，已经有释义的行跳过。格式要求以 `docs/03-素材格式.md` 为准，**开始前完整读一遍**。

**下面所有命令都由你运行，不要让用户手动执行，也不要把命令贴给用户让他去跑。** 用户只看结果。

## 1. 看哪些行要生成

```bash
python3 scripts/material.py words <slug>
```

每一行会标出状态：

- `✓`：已有释义，跳过。
- `·`：待生成，这次要写。
- `✗`：字幕里找不到。先看是不是这几种情况：拼错了、大小写或缩写不同、词形变化（如写了 `push back`，字幕里是 `pushes back`）。
  - 能确定对应哪一处的，照常生成，用「匹配」写上字幕里的原文，汇报时说明你是怎么对应的。
  - 确定不了的不要编，留给用户处理。

没有 `words.txt`，或者没有待生成的行时，告诉用户并结束。

## 2. 读上下文

打开 `en.srt` 和 `zh.srt`（有的话），读每个待生成的词所在的句子和前后几句，弄清它在这里的意思。释义要从这句话出发，不要只给词典义。

## 3. 写释义

读者是正在学英语的中国人，大约 B1 水平，最想知道的是**母语者实际怎么用、怎么说**。`words.txt` 的每一行生成一个词条：

1. **定词条**：用词典原形，占位用 sb / sth。
   - 词条和 words.txt 那一行的原文不同时，写「匹配」，内容是那一行的原文（也就是字幕里的原文）。例如词条 `push back`，匹配 `pushes back`。
   - 那一行开头有 `@7` 这样的句号时，写「句子: 7」。
2. **填字段**：「类型」「本句」必填。单词还要写「词性」和美式「音标」，音标要准确。
3. **写「本句」**：只写它在这句话里的意思，用简短的中文。这是弹层最上面的一行，边听边看，要一眼能懂。
4. **写 5 个标准分节**，标题和顺序固定：

   | 分节 | 要求 |
   |---|---|
   | `### 近义词` | 3–5 个意思相近的词或说法，每个用 `- **词** 中文意思` 的格式。短语的近义词可以是单词，也可以是别的短语 |
   | `### 近义词比较` | 挑最容易混的 2–3 个，逐个和词条比：语气、正式程度、侧重点、搭配有什么不同，什么时候用哪个。每条用 `- **A vs B**：……` 的格式，最好配一个短例句。不要只说“意思相近” |
   | `### 使用场景` | 谁对谁说、在什么场合说（职场、朋友、服务场合……）、语气正式还是随意、常见搭配 |
   | `### 口语化表达` | 母语者日常口语里表达同样意思的更随意、更地道的说法，或这个词在口语里的常见句式。2–4 个，每个用 `- **说法** 中文意思（语气或场合）` 的格式。俚语要注明，不要收冷僻或过时的说法 |
   | `### 例句` | 2 个，自己编，场景和原句不同，贴近日常。英文一行，中文翻译缩进两格写在下一行 |

   实在写不出来时（例如专有名词没有近义词）可以省略某一节，汇报时说明原因。
   其余要求：
   - 需要时可以在最前面加 `### 英文释义`（一句话），在最后加 `### 注意`（常见错误）。
   - 语言简洁，不写空话；拿不准的用法宁可不写。
5. **同一个词条已存在时**：
   - 意思相同：例如 words.txt 里新写的 `pushed back` 和已有词条 `push back` 是同一个意思，就在已有词条的「匹配」后面追加这个写法，不新建词条。
   - 意思不同：另建一个词条，用「句子」字段区分开。
6. **写入 `notes.md`**：
   - 新词条按 words.txt 的顺序追加到文件末尾。
   - 已有词条除第 5 条的情况外不改。
   - `notes.md` 只放词条，开头不要写标题等素材信息（素材信息在 `materials/catalog.json` 里，由 add-material 登记）。

## 4. 校验和构建

```bash
python3 scripts/material.py check <slug>
python3 scripts/material.py words <slug>
```

- `check` 有「错误」就改，直到通过。「缺少标准分节」的提醒，这次新写的词条不应该出现；以前的旧词条出现不用管。
- `words` 里除了你确定不了、留给用户的行，其余都应该是 `✓`。

都通过后生成小程序数据：

```bash
python3 scripts/material.py build <slug>
```

素材还没登记时，build 会提示「跳过构建」。这说明 add-material 还没做完，汇报时告诉用户，释义已经写好，等素材登记后才会出现在小程序里。

## 5. 汇报

简短告诉用户：

- 新增了哪些词条：词条、类型、本句含义、在第几句。
- 哪些已有词条追加了「匹配」。
- 找不到原文、需要用户确认的行，以及你是怎么对应的。
- 省略了分节的词条和原因。

不要改 `words.txt`，也不要自动提交 git。
